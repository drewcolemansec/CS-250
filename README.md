# CS 250 — Software Development Lifecycle

This repository contains my Sprint Review and Retrospective from the SNHU Travel project. During this course, I worked through different Scrum roles and updated a Java slideshow to focus on wellness travel.

## How do I interpret user needs and implement them into a program? How does creating user stories help?

I need to understand what someone wants the program to do before I start changing code. User stories help me turn a general request into something specific that I can work on and check. With SNHU Travel, showing destinations was different from letting someone filter them by price. The slideshow could show the destinations, but it did not have the price filter. Writing the tests made that gap clear. It taught me to ask about missing details instead of assuming I know what the user meant.

## How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I like breaking a project into smaller parts so I can see what is working before moving on. When the travel theme changed to wellness, I kept the slideshow controls and updated the content. Even that took some troubleshooting because the picture filenames had to match what the code expected. That part reminded me to check the small things before spending time looking for a bigger problem. Going forward, I want to keep a prioritized backlog, test changes as I make them, and get feedback before I get too far into the work. Afterward, I want to look at what caused delays so I do not keep making the same mistakes.

## What does it mean to be a good team member in software development?

To me, being a good team member means following through on my work and being upfront when something is not going as planned. If I am stuck, I need to say something while there is still time to figure it out. I would also want to give someone enough information to help, like what I tried and what happened. A feature running on my computer does not mean everyone else can use it yet, so sharing clear testing results matters too. I want people working with me to know where things stand without having to chase me down for an update.
